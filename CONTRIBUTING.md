# Contributing to Glass UI

Thanks for considering a contribution! Bug reports, presets, primitives and docs are all welcome.

## Reporting bugs and suggesting features

- Search [Issues](https://github.com/lemuayala/glass-ui/issues) first.
- Open a new issue with the **Bug report** or **Feature request** form. For styling problems, include a share URL
  from the [playground](https://glass-ui-play.vercel.app/play).
- Security problems go through a [private advisory](https://github.com/lemuayala/glass-ui/security/advisories/new),
  never a public issue (see [SECURITY.md](SECURITY.md)).

## Branches and pull requests

```
feature branch ──PR──▶ dev ──release PR──▶ main ──▶ npm + MCP Registry + GitHub Release
```

1. Fork the repo and branch from `dev` (`feat/…`, `fix/…`, `docs/…`).
2. Open the pull request **against `dev`**. Only maintainer release PRs target `main`, and merging to `main` publishes.
3. CI must pass (lint, typecheck, unit/integration tests with coverage, build, Playwright E2E). Both `main` and
   `dev` require it, and neither accepts direct pushes.
4. Keep each PR focused on one change, and fill in the PR template.

### Commits

Use [Conventional Commits](https://www.conventionalcommits.org/): `feat(core): …`, `fix(landing): …`,
`docs: …`, `ci(release): …`. Each commit should be one self-contained change that builds on its own.

### Changelog

Add user-facing changes under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md). When the maintainer bumps the
version, that section becomes the release notes. CI fails if the current version has no entry.

## Development setup

Requires Node 22+ and **pnpm** (enforced via `preinstall`).

```bash
pnpm install
pnpm dev          # builds the workspace packages, then starts Next.js
pnpm lint && pnpm typecheck && pnpm test
pnpm test:e2e     # Playwright (desktop + mobile)
```

## Technical guidelines

- **Single source of truth:** components are generated by `@lemuayala/glass-ui-core` (`packages/core`). The
  playground, the CLI, the MCP server (`packages/mcp`) and the shadcn registry (`/r`) all use that code, so
  change the templates there and never hand-edit generated output.
- **New primitive:** follow the checklist in [AGENTS.md](AGENTS.md#adding-a-component) (types, CVA variants,
  4 templates, codegen, presets, CLI, MCP, preview, controls, URL state, i18n).
- **Styling:** Tailwind CSS v4 and the glass tokens in `app/globals.css`. Don't introduce a second design system.
- **i18n:** every UI string goes in `lib/i18n/dictionaries.ts` in **English** and **Spanish**.
- **Types:** strict TypeScript. Generated web components must pass the full type-check test
  (`lib/glass-core/codegen-typecheck.test.ts`).
